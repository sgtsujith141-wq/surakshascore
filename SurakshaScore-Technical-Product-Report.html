01 Executive Summary

SurakshaScore (Personal Security Score — PSS) is an on-device digital hygiene evaluation engine and personal security companion built for Indian consumers, professionals, and enterprise users. It evaluates a device's attack perimeter across five primary security vectors: Device Integrity, App Permissions, Network Transport, Account Credential Safety, and Security Habits.

Unlike traditional antivirus or generic security utilities that rely on opaque cloud uploads, battery-draining signature scanning, or arbitrary ratings, SurakshaScore operates on three fundamental engineering invariants:

100% Deterministic Pure Mathematical Scoring Exact deductions with zero arbitrary AI hallucinations or random penalties.
Evidence-Linked 4-Tier Provenance Traceability Every finding is labeled: Verified by OS, App Permission, Self-Reported, or Unavailable.
Zero-Cloud Enclave Complete Privacy Protection Zero telemetry collection. No passwords, contacts, OTPs, or browsing logs leave the device.
02 SIH Problem Statement and SurakshaScore Solution
Smart India Hackathon Problem Statement:

Develop a personal cybersecurity posture and digital hygiene evaluation system that empowers non-technical citizens to measure, understand, and remediate vulnerabilities on their mobile devices without compromising user privacy or requiring complex technical expertise.

How SurakshaScore Resolves the Challenge:

  • Cognitive Clarity: Translates 40+ complex security signals into a single unified 0–100 Hygiene Index with plain-English status headlines (*"Your device security is strong"*, *"2 urgent issues require attention"*).
  • Actionable Remediation: Instead of generic alerts, provides a step-by-step Point Recovery Simulator showing exact point gains (e.g., +16 pts: Enable Biometric Screen Lock).
  • Platform Adaptability: Normalizes Android vs. iOS security boundary differences through mathematical weight redistribution.
  • Verifiable Trust: Built-in zero-knowledge tools (k-Anonymity password check, offline password vault, heuristic URL analyzer) operate locally without centralized logging.

10 & 31 4-Tier Evidence Provenance System

SurakshaScore rejects the common industry practice of treating all data sources identically. Every signal and finding carries an explicit provenance tier with a mathematical confidence multiplier:

Tier Badge Provenance Key Confidence Multiplier Description & Example
✓ Verified by OS VERIFIED 1.0 (100%) Obtained directly via immutable hardware keystore or OS kernel API (e.g. Screen lock enabled, Disk encryption active).
◉ App Permission PERMISSION_BASED 1.0 (100%) Declared directly in OS package manifests inspected via PackageManager (e.g. Accessibility service active, SMS background permission).
◇ Self-Reported SELF_REPORTED 0.6 (60%) Reported by user in security habit assessments (e.g. password manager usage, offline recovery keys). Penalty is scaled down to prevent unfair deductions.
— Unavailable UNAVAILABLE 0.0 (0%) Signal blocked by OS sandbox (e.g. querying other apps on iOS). Deductions are zeroed out and category is redistributed.
12–16 Exact Scoring Engine Mathematics & Code Trace

The scoring engine implemented in src/lib/scoring.ts is 100% deterministic pure math.

1. Category Score Formula:
CategoryScore[c] = max(0, min(100, 100 - Σ ( SeverityPenalty[f] × ConfidenceMultiplier[p] ) ))

Where \( f \) ranges over all open findings in category \( c \), and \( p \) is the provenance of finding \( f \).

2. Overall Hygiene Index Formula:
OverallScore = round( Σ ( AdjustedWeight[c] × CategoryScore[c] ) )

Where \( \text{AdjustedWeight}[c] = \frac{\text{BaseWeight}[c]}{\sum_{s \in \text{ScoreableCategories}} \text{BaseWeight}[s]} \).

A. Base Category Weights (Sum = 1.0)

17 & 18 End-to-End Score Calculation & Deductions Analysis
Crucial Scoring Insight (§18): Why an app shows an 84 score while displaying large risk penalties:

A common point of confusion for judges is seeing a "Critical (-40 pts)" finding while the overall score drops from 100 to only 85. This is by design and mathematically correct: Deductions are applied to the Category Subscore (0–100), which is then multiplied by the Category Weight (25%). A -40 pt deduction in Device Security reduces the Device Subscore from 100 to 60. The net contribution to the overall score is \( 60 \times 0.25 = 15\text{ pts} \) instead of \( 25\text{ pts} \), resulting in an exact -10 pt delta on the overall score!

Real Example from the Active "Student" Demo Profile:

Category Active Open Findings Penalties × Multipliers Category Score Weight Points Contributed
Device 1 Medium (Developer Options active) 10 × 1.0 = 10 100 - 10 = 90 0.25 22.50 pts
Apps 1 High (Unnecessary Background SMS) 20 × 1.0 = 20 100 - 20 = 80 0.25 20.00 pts
Network 0 (Clean WPA3 + VPN) 0 100 - 0 = 100 0.15 15.00 pts
Account 1 High (Edmodo breach found) 20 × 1.0 = 20 100 - 20 = 80 0.20 16.00 pts
Habits 1 Medium (Self-reported password reuse) 10 × 0.6 = 6 100 - 6 = 94 0.15 14.10 pts
FINAL COMPUTED SCORE: round(22.50 + 20.00 + 15.00 + 16.00 + 14.10 = 87.60) 88 / 100 (Good)
